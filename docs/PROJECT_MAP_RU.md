# Dungeon Travelers 2 (PC) — карта проекта, реверс движка и путь на Android

Документ собирает в одном месте: состав проекта, результаты реверса, форматы
данных и реалистичные варианты «восстановления движка» / порта на Android.

---

## 1. Что за проект

Русская локализация **Dungeon Travelers 2: The Royal Library & The Monster Seal**
(PC, ENG 1.0, `DT2_en.exe`). Сделано без DLL/ASI: текст, шрифт, `Parameter` и
статический патч exe. Оригиналы сохраняются рядом (`.orig`, `Parameter_orig`,
`DT2_en.clean.exe`).

Корень рабочей папки (пример): `...\DungeonTravelers2_EN\`.

## 3. Реверс движка (сводка)

### 3.1 Бинарь

| Параметр | Значение |
|---|---|
| Формат | PE32, x86 (32-бит), ImageBase `0x400000`, ASLR выключен |
| Графика | `d3d11.dll`, `dxgi.dll` (D3D11) |
| Ввод | `DINPUT8.dll`, `XINPUT1_3.dll` |
| Видео | `avformat-58` / `avcodec-58` / `avutil-56` / `swscale-5` (ffmpeg) |
| Секции | `.text 0x1000`, `.rdata 0x198000`, `.data 0x27F000`, `_RDATA 0x40433000`, `.rsrc 0x40434000` |

### 3.2 Ключевые адреса

| Адрес | Что |
|---|---|
| `0x447950` | `FindGlyph`: отрисовка глифа (out, code, x, y, color, sx, sy) |
| `0x4477A0` | разбор CFont (текстура, cell, count, entries 12 B, U/V) |
| `0x464FF0` | выбор шрифта по коду: `<0x7D0` → `[0x6E5984]`, иначе `[0x6E59D0]` |
| `0x464F70` | advX по коду; `0x464FB0` — advY |
| `0x51B370` / `0x51B390` | `fld [[this+0xC]+code*32+8/0xC]` (advX/advY CSpriteParts) |
| `0x4632C0` | `CStringBase::draw`; `0x465940` — `CStringCursor::draw` |
| `0x4634xx` | цикл раскладки/отрисовки строки (`esi += 0x20` по записям глифов) |
| `0x4651D0` | «ширина по коду» (обёртка advX + округление `0x588490`) |
| `0x6E5984`, `0x6E59D0` | объекты шрифтов (CSpriteParts, vtable `0x65C280`) |
| `0x6E59B0` | массив указателей на шрифты по размеру (60/48/44/40/36/32) |
| `0x65C280` | vtable CSpriteParts: `+0xC` advX, `+0x10` advY, `+0x14` load |

### 3.3 Текст

- PCK: заголовок `Filename` / `Pack`, таблица `(offset,size)`, блобы
  `*.adv.bin`.
- В каждом текстовом чанке первые **3 байта — ID говорящего**
  (`FF FF FF` = без имени). Если их заменить текстом, движок ест первые буквы,
  а плашки ломаются. `pack_ru.py` их сохраняет.
- Строки разделены `NUL`; переносы в переводе заданы вручную (`\n`), поэтому
  метрики движка на разбивку не влияют.
- Транслитерация: кириллица кодируется ASCII-кодами, в шрифтах на этих кодах
  лежат кириллические глифы (`translit.py`).

### 3.4 Шрифты

- `Font1.pck` / `Font2.pck`: чанки `Table` (записи 12 B: code, U, V) и
  `Texture` (RGBA, RGB=A), 672/… глифов, ячейка 56/68.
- `UI.tex`: `Parts` 952 записи по 32 B; `UI2.tex`: `Parts` 161 запись.
  Формат записи: `offsetX, offsetY, W, H, u0, v0, u1, v1`.
- **Поле `+8` не является advance**: маркеры 999/888 в памяти игра видит, но
  шаги не меняются (space 18, `i` 11, `w` 45). Шаг считается кодом раскладки;
  ширины задаёт стаб патча.

### 3.5 `Parameter`

- 27 `.bin`: таблица записей + строки (имена/описания) в конце.
- `pack_param.py` дописывает перевод в конец, патчит найденные 32/64-битные
  указатели; исходные данные не удаляются, поэтому непропатченные ссылки
  остаются валидными.
- Покрытие неполное: часть строк не попала в `parameter.ru.tsv`.

### 3.6 Статический патч `.rufix`

- Новая секция RVA `0x4043A000`, флаги `0xE0000060`, `SizeOfImage += 0x1000`.
- В `0x447950` — `E9 rel32`; стаб (98 байт): `pushad`, чтение code/x/y,
  сброс курсора на новой строке (`x <= lastX` или смена `y`), стартовый отступ
  **22 px**, `cursor += g_w[code]`, `popad`, украденный пролог, `jmp 0x44795A`.
- Таблица ширин `g_w[256]` — из `hookfont.cpp` (ink × 1.2 + 2, минимумы для
  пунктуации, пробел 14).
- DLL/ASI не нужны; всё в exe.

## 4. Что ещё не раскрыто

1. Точная формула advance в раскладке (шаг не берётся из `Parts +8`).
2. Плашки имён части персонажей — латиница (имя лежит отдельной строкой скрипта).
3. Титры интро и логотип меню — графика/видео, не текст.
4. Часть `Parameter` не переведена (не было строк в TSV).
5. Форматы CG/WorldMap (`CG_EN.pck`) не разбирались.

## 6. Путь на Android

Движок — **Win32 x86 + D3D11**. APK требует ARM; автоматической конвертации нет.

### Вариант A. Winlator / Box86 + Wine + DXVK (реалистично)

- 32-битный x86 через Box86, D3D11 → Vulkan через DXVK.
- Игра 2D, нагрузка умеренная; шансы средние-хорошие.
- Это не «порт», а контейнер; можно сделать ярлык «как приложение».
- Проверять на устройстве: DXVK-версия, Box86, ffmpeg-DLL, ввод.

### Вариант B. Гибрид: эмулятор + HLE

- Взять ядро Wine/Box86 и заменить подсистемы (текст/скрипты) на нативные.
- Требует восстановления форматов и точек входа — недели/месяцы.

### Вариант C. Ремейк (Godot/Unity)

- Разложить ассеты (PCK/tex/parameter), воспроизвести бой и сюжет.
- Месяцы; зато нативный Android/PC и переносимость.

### Что нужно для «компилятора под Android»

1. Статический рекомпилятор x86→ARM (готовых промышленных нет; энтузиастские
   проекты вроде Box86 — интерпретатор/JIT, а не компилятор).
2. Либо декомпиляция в C (Ghidra) + NDK: нереально для всего движка, но
   возможно для отдельных подсистем (текст, скрипты).
3. Практичный минимум: APK-обёртка с Wine/Box86 + игрательные настройки.
